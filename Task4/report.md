# Задание 4. Отчёт: узкие места при миграции

## 1. Ситуация и цель миграции

**As-Is:** учёт на Excel/файловом диске, 1С в файловом режиме, один Windows Server в офисе, интеграции OLE/TCP (KKM↔1С), нет горизонтального масштабирования.

**To-Be:** микросервисная платформа (Portal, CRM, Payment, Lab Integration) + контур Privacy by Design (см. Task2), рост нагрузки до ×5, филиалы, мобильный ЛК.

**Риск миграции:** в переходный период и сразу после cutover возможна деградация latency/throughput, ошибки интеграций и простой ключевых процессов (запись, карта, оплата).

Диаграмма Исикавы: [`ishikawa-migration.drawio`](ishikawa-migration.drawio).

## 2. Компоненты и процессы под ударом

| Область | Что затрагивается |
|---------|-------------------|
| Данные | Excel → Postgres/object store; качество, индексы, объём сканов медкарт |
| Коммуникации | замена OLE/файловых обменов на API/события; Lab, KKM, 1С |
| Инфраструктура | уход с одного сервера на K8s/облако или гибрид; сеть филиалов |
| Бизнес-логика | запись к врачу, медкарта, оплата, ТМЦ — разнесение по сервисам |
| Персонал/процессы | малый IT, обучение клиники, нагрузочные тесты, rollback |

## 3. Причины по категориям (с диаграммы)

### Инфраструктура
- единый сервер в здании — SPOF в момент cutover;
- нехватка CPU/RAM/IOPS под рост ×5 и пики записи;
- отсутствие готового горизонтального масштабирования (K8s/HPA);
- узкий канал между филиалами и ЦОД/облаком.

### Программное обеспечение / сервисы
- «чатти» микросервисы (N+1 вызовов Portal→CRM→Lab);
- холодный старт JVM / неоптимальные лимиты;
- нет кэша и настроенных connection pool к БД;
- длинные синхронные цепочки без асинхронности.

### Интеграция
- OLE/TCP KKM→1С не масштабируется и плохо наблюдается;
- Lab API без SLA, таймаутов и backpressure;
- период двойной записи (Excel + новая БД) удваивает нагрузку и риск рассинхрона;
- нет идемпотентности и единой retry/circuit-breaker политики.

### Данные
- «грязная» миграция Excel (дубликаты, разные форматы ФИО/дат);
- крупные PDF/JPG карт без object storage/CDN;
- тяжёлые запросы без индексов и partitioning;
- синхронная репликация как тормоз записи.

### Персонал
- IT из 3 человек на миграцию и сопровождение;
- дефицит опыта K8s/Java у части команды;
- ресепшен/врачи не обучены новому UI → ошибки и «обходные» Excel;
- bus factor на техническом директоре.

### Процессы
- нет полноценного нагрузочного тестирования до cutover;
- parallel run без сравнимых SLO-метрик old vs new;
- слабый rollback / runbook;
- инцидент-менеджмент не готов к режиму 24/7 ЛК.

## 4. Рекомендации и приоритеты

Шкала приоритета: **P0** — до/на cutover, иначе высокий риск простоя; **P1** — в MVP-окне; **P2** — сразу после стабилизации.

| # | Мера | Устраняет | Приоритет |
|---|------|-----------|-----------|
| 1 | Вынести прод с единственного офисного сервера; staging + prod в K8s/облаке с HPA | Инфраструктура / SPOF | **P0** |
| 2 | Нагрузочные тесты сценариев «запись + карта + оплата» на ×5; зафиксировать SLO | Процессы / ПО | **P0** |
| 3 | План отката и feature flags / dual-read; runbook на cutover | Процессы | **P0** |
| 4 | Миграция данных: cleansing, дедуп, репетиция migrate+verify | Данные | **P0** |
| 5 | API Gateway + таймауты, retry, circuit breaker, идемпотентные ключи | Интеграция / ПО | **P0** |
| 6 | Заменить OLE-канал оплаты на Payment Gateway (TLS), убрать Excel-дубль | Интеграция | **P0** |
| 7 | Снизить chatty-calls: BFF/агрегация, async для Lab и уведомлений | ПО | **P1** |
| 8 | Индексы, partitioning, object storage для сканов; кэш горячих чтений | Данные / ПО | **P1** |
| 9 | Parallel run с дашбордом сравнения latency/error rate old vs new | Процессы | **P1** |
| 10 | Lab: контракт SLA, rate limit, очередь с backpressure | Интеграция | **P1** |
| 11 | Найм/ауткинг под K8s и Java; парное сопровождение cutover | Персонал | **P1** |
| 12 | Обучение ресепшена/врачей; запрет «теневых» Excel после go-live | Персонал / Процессы | **P1** |
| 13 | Расширить канал/CDN для филиалов; асинхронная репликация отчётов | Инфраструктура / Данные | **P2** |
| 14 | On-call и инцидент-процесс под 24/7 ЛК | Процессы / Персонал | **P2** |

## 5. Вывод

Главные угрозы производительности при миграции — не «микросервисы сами по себе», а **сочетание**: слабая инфраструктура As-Is, синхронные интеграции, грязные данные Excel и отсутствие perf/rollback-процессов при маленькой IT-команде. Закрытие **P0**-мер до cutover снижает риск деградации записи, оплаты и доступа к картам в момент перехода.
